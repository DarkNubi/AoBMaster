# **AoBMaster v1.0**

### Stable, Address-Anchored, Multi-Version AoB Synthesis Tool

**CLI-only · Deterministic · Standalone**

This document is **self-sufficient**.
If this is the *only* document given to a competent software engineer, they should be able to implement **AoBMaster v1.0 completely and correctly**, with high confidence.

---

# 0. Executive Summary (Non-Negotiable Intent)

**AoBMaster** is a command-line tool that **automatically synthesizes stable Array-of-Bytes (AoB) signatures** from a known anchor address in a binary, and **validates their robustness across multiple versions** of that binary.

AoBMaster replaces manual AoB crafting by:

* instruction-aware normalization
* systematic candidate generation
* empirical, cross-version validation
* deterministic scoring and ranking

AoBMaster is:

* ❌ not Cheat Engine
* ❌ not a trainer generator
* ❌ not game-specific
* ✅ a **binary analysis and signature synthesis system**

# 3. Core Concepts & Terminology

### Anchor

A **known location of interest** in the base binary, provided by the user, expressed as:

* RVA (preferred)
* File offset
* Virtual address

### Base Binary

The binary from which AoB candidates are generated.

### Version Set

The base binary plus zero or more additional binaries assumed to be **the same program across versions**.

### Stable AoB

An AoB pattern that:

* Exists in all binaries in the version set
* Is unique in each binary
* Is resilient to relocation and recompilation noise

# 5. `aobmaster synth` — Core Command

## 5.1 Purpose

Generate, validate, rank, and output **stable AoB signatures**.

---

## 5.2 Required Inputs

### Base Binary

```bash
--base <path>
```

### Anchor (exactly one)

```bash
--anchor-rva <hex>
--anchor-fo  <hex>
--anchor-va  <hex>
```

---

## 5.3 Optional Inputs

### Additional Versions

```bash
--versions <path>...
```

If omitted, AoBMaster runs in **single-version mode**.

---

## 5.4 Anchor Alignment Across Versions

Default behavior:

```bash
--align bytespan
```

### Supported modes

#### `anchor-rva`

Assumes identical RVA across binaries.

#### `bytespan` (DEFAULT)

* Extracts a raw byte seed around the base anchor
* Searches for that seed in each version
* Aligns anchors empirically

Parameters:

```bash
--seed-bytes 32        # default
--seed-scan section   # section | module
--seed-allow-multi false
```

Failure to align a version **fails the run** unless explicitly overridden.

# 6. Disassembly & Anchor Resolution

## 6.1 PE Mapping

Engineer must implement:

* RVA ↔ File Offset translation
* Section boundary detection
* Executable section identification

## 6.2 Instruction Boundary Recovery

If anchor is not aligned:

* Backtrack up to 15 bytes
* Attempt resynchronization
* Emit warning if resynced
* Fail if impossible

# 7. Context Extraction

Defaults:

```bash
--context-before 8
--context-after  8
--max-context-insns 32
```

Context is measured in **instructions**, not bytes.

---

# 8. Instruction Normalization Rules (CRITICAL)

Normalization must use **decoded instruction semantics**, not heuristics.

### Always Wildcard

* RIP-relative displacements (`disp32`)
* Relative branch immediates (`call`, `jmp`, `jcc`)
* Stack offsets (`[rsp+X]`)
* Heap/base offsets (`[reg+X]`)

### Always Preserve

* Opcode bytes
* Mandatory prefixes
* ModRM
* SIB
* Condition codes

### Optional (off by default)

* Immediate constants (`imm32`, `imm64`)

Profiles:

```bash
--profile default | strict | aggressive
```

---

# 9. Candidate Generation

Candidates are generated by:

* Sliding instruction windows
* Must include anchor instruction
* Instruction count between:

```bash
--min-insns 6
--max-insns 14
```

Hard rejections:

* Wildcard ratio > 45%
* Total byte length > 64
* Empty fixed-byte prefix

---

# 10. Pattern Scanning & Validation

## 10.1 Scan Domains

```bash
--scan-range section | module
```

Defaults:

* Base: section
* Versions: module

## 10.2 Validation Rules

A candidate is **valid** if:

* Matches **exactly once** in base
* Matches **≥1 times** in all versions
* Matches **≤1 time** in all versions (unless overridden)

Defaults:

```bash
--require-unique true
--require-present-all true
```

---

# 11. Scoring & Ranking

Each candidate receives:

### Components

* **U**: Uniqueness (hard gate)
* **P**: Presence across versions
* **S**: Specificity (1 − wildcard ratio)
* **L**: Length regularization
* **A**: Anchor proximity

### Default Formula

```
score = 0.35U + 0.25P + 0.20S + 0.10L + 0.10A
```

### Confidence

Derived from:

* Number of versions
* Drift magnitude
* Alignment ambiguity
* Resync warnings
